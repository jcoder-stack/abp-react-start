# Spike：退回 shadcn 原版 + Blue 主色

问题：这套 Linear-informed 的自定义主题值不值得维护？还是保留 shadcn 原版设计、只换蓝色主色更好？

方法：用 `shadcn@latest init --preset b1Ymqvgiu --base radix --template start --monorepo` 生成一份原版蓝主题，与现仓主题**跑同一套 Tailwind 基底、同一份类清单**编译，唯一变量是令牌本身；再用同一份表单/记录卡原型并排渲染，浅暗两色实测。

---

## 一、维护成本：证据来自这一轮自己踩的坑

这一轮修过的七类问题，按「问题从哪来」分：

| 修的问题 | 根因 |
| --- | --- |
| 中文字重被取整、字距挤死 | **510/590 + 逐档负字距** |
| 浅色下文字阶梯 / 状态药丸 / 按钮白字不合规 | 自定义色阶 |
| 移动端输入框触发 iOS 整页放大 | **重定义 `--text-base` 为 14px** |
| 刻度 11 档只用 3 档 | 自定义刻度，结论是**还原成原版的 16px** |
| 圆形图标钮只命中 22 个里的 2 个 | 自定义规则 vs `asChild` 改写 slot |
| 七处文档与实现脱节 | 半数是自定义阶梯与焦点环 |
| 表单设计、关闭闸门 | **与主题无关**，是组件设计 |

**七个里有五个，修的是自定义本身造出来的问题。**

更彻底的一点：**中文适配是被自定义排版催生的。** 510/590 在中文离散字重上会向上取整、负字距把汉字挤死，所以才有那 33 行 `:lang(zh)` 覆盖。原版**零字重自定义、零负字距**——这个问题根本不存在。同理 iOS 缩放那条：原版 `text-base` 就是 16px，iOS 那道保险自己成立。

## 三、原版蓝的对比度实测（浅色）

| 配对 | 实测 | 判定 |
| --- | --- | --- |
| primary 承 primary-foreground | 6.26:1 | 过 |
| foreground / bg | 19.79:1 | 过 |
| muted-foreground / bg | 4.73:1 | 过 |
| destructive 承白字 | 4.76:1 | 过 |
| **ring / bg（焦点环，需 ≥3）** | **2.59:1** | **✗ 不过** |

原版唯一的合规缺口是焦点环——它用的是中性灰 `oklch(0.708 0 0)`。一行可修（指向 primary）。

**它的蓝比我们的深**：承白字 6.82:1（我们 5.08:1）。这带来一个直接简化——同一个蓝既能当填充又能当前景，**`primary-bright` 这个令牌可以整个删掉**（它当初存在，正是因为我们的蓝太浅、当文字对比度不够）。

原版还自带 `--chart-1..5`——那是我们评审里记着的空白之一。

## 四、密度：我之前的判断是错的

原以为「原版是营销页尺度、后台需要更密」是保留自定义主题的硬理由。实测推翻了它：

**同一份五字段表单，两套主题下都是 425px。**

因为密度实际由**类的选择**决定（`h-9` 控件 36px、`gap-5` 间距 20px），那些来自 Tailwind 默认间距刻度，**两套主题都没有动它**。主题真正改变的只有三件事：

| | 现仓 | 原版 |
| --- | --- | --- |
| `text-sm` 的含义 | 13px | 14px |
| 控件圆角 | 6px | 8px |
| 主色 | `oklch(0.55 0.21 264)` | `oklch(0.488 0.243 264.376)` |

表格行高也不受影响——它已经是组件里声明的 `[&_td]:h-10`（40px），与主题无关。

所以密度只剩**一个杠杆**：`--text-sm`。想要 13px，保留一行即可。

## 五、观感差异

并排渲染（同一份原型、浅暗两色）：原版字略大、圆角略软、蓝更深更饱和；现仓更紧、更冷、更「工具感」。差异真实存在，但比预期小得多——自定义主题的「气质」大部分落在很难被用户察觉的层面（阶梯、发丝线权重、五层阴影）。

## 建议

**退回原版，加一层薄覆盖。** 该保留的只有五类：

0. **强调色仍用自家的蓝** —— 采用原版的**体系**不等于采用它的**强调色**；强调色恰恰是 preset 预期被替换的那一个。而且自家这支是往正确方向调的：

   | | 承白字 | 对页底（链接 / 当前项 / 焦点边框） |
   | --- | --- | --- |
   | 自家 浅 0.55 → 暗 0.57（**变亮**） | 5.08 / 4.66 | **5.08 / 4.24** |
   | preset 浅 0.488 → 暗 0.424（**变暗**） | 6.82 / 8.84 | 6.82 / **2.24 ✗** |

   preset 那支在暗色下压在近黑页底上只有 2.24:1，必须为暗色另开一条焦点环特例。换回自家的蓝，那条特例可以删掉——**一个色值，两个主题，两种用途**。

1. **`--ring` 指向 primary** —— 修掉原版自己 2.59:1 的焦点环缺口；换回自家蓝之后两个主题都够（5.08 / 4.24）。
2. **`--text-sm: 0.8125rem`（13px）** —— 唯一的密度杠杆，一行。
3. **CJK 字体回退栈** —— 原版完全没管，双语产品的刚需。
4. **`status-*` 五档 + 暗色** —— CRUD 后台靠颜色表达状态，原版没有这一组；沿用已实测合规的值。

**该删的**：510/590 字重、逐档负字距与整个 11 档刻度、四级 surface 阶梯 + 三级 border 阶梯、五层模态阴影、圆形图标钮规则、`cv01/ss03`、brand-mark 光学补偿、`primary-bright/hover/focus`、`row-selected`、`surface-overlay`、`foreground-disabled`、以及**整个 `:lang(zh)` 字重与字距覆盖**（失去存在理由）。

**不受影响**：表单设计与关闭闸门是组件层的，原样保留。表格密度也是组件层的。

**代价**：全站视觉回归要逐屏看；`DESIGN.md` 会从 870 行缩到很小——这既是代价也是收益，一份每次改动都要同步的规范本身就是负担。

### 一句话

自定义主题的收益是「更像一件工具」，成本是这一轮的五次返工。而它带来的密度优势，实测只值一行 `--text-sm`。

**要换的是体系，不是颜色。**
