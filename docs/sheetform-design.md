# SheetForm 设计提案

对侧滑表单的观感与用法所做的设计提案。功能与规范层面的缺陷另见 [`sheetform-review.md`](sheetform-review.md)——那份是「坏了」，这份是「不够好」。

提案已用仓库真实 token 做成可视稿（见文末），浅色与暗色都验过。

---

## 一、节奏：让间距承担分组

**现状**：标签→控件 12px，字段→字段 16px（实测）。

1.33 倍的差读不出层次——一个标签和它自己的控件，与两个毫不相干的字段之间，几乎一样远。而 `DESIGN.md` 自己的规则是「相关的靠紧、不相关的拉开，**间距本身就是分组信号**」。现在这个信号没发出来。

**提案**：

| 关系 | 间距 | 比例 |
| --- | --- | --- |
| 标签 → 它的控件 | **6px** | 1 |
| 字段 → 字段 | **20px** | 3.3 |
| 分组 → 分组 | **32px** | 5.3 |

三级之间是能一眼看出的倍数关系。字段区横向内距同时从 16px 放到 **20px**——448px 宽的面板里，16px 显得贴边。

## 二、必填：不要红星，标「选填」

**现状**：必填字段的标签后跟一个 `destructive` 红星。

红在这套系统里只有一个含义——出错与危险（`DESIGN.md`：「destructive 仅用于不可逆动作与错误态，绝不装饰」）。用它标必填，等于让一个还没被碰过的表单上布满错误信号；等真的出错时，红色已经贬值了。

而且方向反了：图书表单 5 个字段里 **4 个是必填**。标 4 个红星，不如标 1 个「选填」。

**提案**：**标少数派**。必填占多数时，只给选填字段一个 `muted-foreground` 的「选填」后缀；选填占多数时反过来标必填，同样用 muted 而非红。红色留给错误。

> 无障碍上不受影响：`aria-required` 仍由字段组件给出，不依赖视觉标记。

**这个开关必须放在表单层，不能放在字段层。** 实施时第一版让每个非必填字段自动挂标记，结果**查询表单**的每个标签都变成了「X 选填」——筛选条件本来就全是选填，逐个标等于每条都挂一句废话。少数派是谁取决于整张表单的构成，字段自己看不到这件事。

最终实现是一个 `OptionalMarks` context：`SheetForm`（录入，多数必填）打开它，查询表单不打开。字段 API 一个字没改。

> 这条是被测试逼出来的：改完之后 9 个用例挂掉，其中 6 个都是查询表单里 `getByLabelText("Name")` 找不到标签——标记把可访问名字改了。测试在这里替真实用户先叫了一声。

## 三、占位符要教格式，不要预填值

**现状**：价格字段预填 `0`，日期字段显示 `mm/dd/yyyy`。

预填值有两处伤害：用户得先删掉它才能输入；而 `0` 能通过非空校验，于是那个必填星号永远不会触发——一个假的必填。

**提案**：

| 字段 | 现状 | 提案 |
| --- | --- | --- |
| 价格 | 值 `0` | 占位 `0.00` |
| 出版日期 | 占位 `mm/dd/yyyy` | 占位 `年 / 月 / 日` |
| 名称 | 无 | 占位 `例如：三体` |

占位符的职责是示范格式，不是充当默认值。日期那条同时解决了中文界面显示英文日期格式的问题（该字段本应改用仓库自带的 `DateField`，见 review 的 B5）。

## 四、说明文字放在标签下，不放控件下

控件**下方**是错误信息的位置。说明文字也挤在那里，出错时两者会互相顶替——要么说明消失，要么错误被推走。

**提案**：说明（12px / `muted-foreground`）紧跟标签、在控件之上；控件下方永远留给错误。这样一个字段的纵向顺序恒定：**标签 → 说明 → 控件 → 错误**。

## 五、底部：单行右对齐，取消用 ghost

**现状**：两个全宽按钮竖排，共占 112px（实测），是面板高度的两成。

两个带边框/填充的按钮并排会互相竞争视觉重量，而「取消」根本不需要争。

**提案**：单行、右对齐、**primary 最右**（与整页表单同一套语法）；取消改 **ghost**——它是退路，不是选项。底部内距 12px / 20px，比现状矮一半还多。

**上边框只在内容可滚时出现。** 边框在这里是「上面还有东西」的信号，不是装饰；内容一屏放得下时画一条线，是在说一件不存在的事。

## 六、查看态是定义列表，不是禁用表单

**现状**：`view` 模式把所有控件 `disabled`。

禁用控件的对比度是 WCAG 明确豁免的——**因为它不承载内容**。用一排灰掉的输入框去展示一条记录，既难读，又像坏了；用户还会去点那些框。

**提案**：查看态复用**整页表单的容器语汇**——`divide-y rounded-lg border bg-card`，一行一个字段。

| | 排版 |
| --- | --- |
| 行 | 高 40px（与表格行高同源），`justify-between`，横向内距 12px |
| 键 | 13px / 400 / `muted-foreground`，左 |
| 值 | 13px / 400 / `foreground`，**右对齐** |
| 空值 | 13px / `muted-foreground`，文案「未填写」 |
| 枚举值 | 用 `StatusBadge` 而不是纯文本 |
| 数字与时间 | `tabular-nums`，金额带 `¥` 前缀 |
| 卡片分组 | 业务字段一张卡，审计字段（创建人、创建时间）另起一张 |

三点理由：

1. **右对齐让值排成一条竖线**，扫视时眼睛只走一列；左对齐的值会随标签长短参差，正是初稿看着松散的原因。
2. **行高 40px 与表格一致**——一条记录读起来就像「把一行表格竖过来」，这是系统里已经存在的语汇，不必新造。
3. **卡片把内容收成一块**。初稿的键值对直接浮在面板底色上，六行文字撑不住 448×552 的面板，下半部分空得像没做完；有了边框，空白就读作「卡片下方的留白」而不是「内容缺失」。

标题区同时改成**记录标识**：主标题是记录本身（「三体」），紧随其后是状态/枚举徽标，副标题放次级标识（「刘慈欣 · 2008-01-01」）。**正文里不再重复标题已经说过的字段**——初稿第一行是「名称：三体」，占一行却什么都没告诉人。

> **这一条实现里没有做，是有意的。** 真实页面上标题是「1984」、第一行仍是「名称 1984」。要去重只有两条路：按值相等自动隐藏（两个字段恰好等于标题时会连坐，是会咬人的魔法），或者让调用方声明「哪个字段是标题」（新增一处 API）。而一份**完整、可预期**的字段清单本身有价值——读者不用猜「标题里那个值到底是哪个字段」。所以保留重复的那一行，等真有第二个页面也嫌它多余时再加 API。

**实现上的分工：渲染归字段，容器归表单。** 只有字段自己知道该把枚举值显示成哪个 label、把布尔显示成「是/否」、把日期显示成什么格式，所以每个字段给出自己的 `display`；`SheetForm` 在 view 模式下提供 `ReadOnlyFields` context 和那个 `<dl>` 容器。**调用方的写法一个字都不用改**——同一份 `<field.TextField label=… />` 在录入态是输入框，在查看态是一行键值。

没接上 `display` 的字段（DateTime、DateRange、MultiCombobox）会回退到原来的禁用控件，不会碎掉；补齐是后续的事。

## 七、分组要够长才值得

5 个字段分两组是过度结构：分组线本身成了噪声，而它要解决的问题（找不到字段）还不存在。

**提案**：**约 7 个字段以下不分组**，一列连续流即可；超过之后分组开始还本。分组标题 13px / 590 / `foreground` + 一条 `border-subtle` 发丝线，组间 32px。

## 八、标题要有宾语，副标题只在有信息时才出现

**现状**：标题是「新增」——没有宾语，不知道在新增什么；由 `useAbpSheet` 用 `Crud:Create` 词条硬给，调用方补不上。

**提案**：

| 模式 | 标题 | 副标题 |
| --- | --- | --- |
| 新建 | 新建图书 | 无 |
| 编辑 | 编辑租户 | Contoso · 已启用 |
| 查看 | 三体 | 刘慈欣 · 2008-01-01 |

副标题只承载**记录标识或状态**。写「保存后可在列表中继续编辑」这类话不如不写——它占一行，读者一次就不再看第二次。

## 九、手艺：借 shadcn 自己的表单语汇

前面几条讲的是结构，这条讲观感。让一张 shadcn 表单「看起来是被设计过的」，靠的是几处很小的东西，本仓的原语里全都有，只是 SheetForm 没有用起来：

- **控件的 `shadow-xs`。** 一道几乎看不见的投影，是输入框读作「被放在纸上」而不是「被画在纸上」的全部原因。`Input` / `SelectTrigger` 原语自带，别覆盖掉。
- **6px 圆角**（`rounded-md`，控件档）。控件 6 < 卡片 8 < 面板 12 这条梯子在 `DESIGN.md` 里已经写死，照用即可。
- **图标一律 lucide、16px、`muted-foreground`**：下拉用 `ChevronDown`，日期用 `Calendar`，关闭用 `X`，查看转编辑用 `Pencil`。**不要 emoji**——emoji 有自己的字族、自己的配色和自己的基线，放进一套单色线性图标里必然出戏。
- **分区 = 标题 + 一句说明 + 分隔线**。这是 shadcn 自家 settings 表单的惯用法，比「一行小标题加下划线」更有呼吸：`text-sm font-medium` 的标题、`text-xs text-muted-foreground` 的说明、组间 `h-px bg-border`。
- **金额字段把货币符号放进框内左侧**（`¥`，`muted-foreground`，`pl-7`）。它同时是标签、是格式提示，还省掉了一行说明文字。
- **查看态用两列定义列表**（标签列定宽 100px），键值在 `items-baseline` 上对齐。比上下堆叠更紧凑，也更像一张「记录卡」。

> 第一版可视稿里控件是方角的——那是稿子的毛病不是提案的主张：我手写 CSS 消费了 `var(--radius-md)`，而编译时没带任何工具类，`@theme inline` 的变量在没有使用点时不会输出，于是圆角落空。第二版改为**直接使用真实组件的类串**（`Input`、`Button` 的 cva、`SelectTrigger`），既保证视觉一致，也让提案能一比一翻译成代码。

## 十、CJK 下不用 label-caps

分组标题和查看态的键名，第一版草稿用的是 `label-caps`（11px 全大写）。这违反本仓已有的规则：中文没有大小写变换，`uppercase` 是空转，11px 对着 13px 就是实打实小一号。`DESIGN.md` 已为表头写过这条，它对**所有**用 `label-caps` 的位置都成立。

**提案**：CJK 语境下这两处都用 13px，区分交给字重与颜色。

## 十一、空值提示用 muted，不用 disabled

「未填写」这类占位文案是**内容**，不能用 `foreground-disabled`——那一档在浅色下只有 2.71:1，它能豁免正是因为它不承载内容。用 `muted-foreground`（5.52:1）。

## 可视稿

四个面板：现状 / 提案·新建 / 提案·查看 / 提案·长表单。**用真实组件的类串渲染**（CSS 由 `examples/starter/src/styles.css` 按稿中实际出现的类编译），浅色与暗色均已验证。

源文件：`scratchpad/v2.html` + `v2.css`。

## 实施顺序建议

1. **三、五、八** —— 占位符、底部布局、标题宾语。改动小，收益立刻可见。
2. **一、二、四** —— 节奏、必填标记、说明位置。要动 `FieldShell` 与 `SheetForm` 的骨架。
3. **六** —— 查看态改定义列表。是新增一种渲染，工作量最大，但也是观感提升最大的一条。
4. **七、十、十一** —— 分组阈值与 CJK / 色阶的细则，随上面几条一起落。

**九（手艺那条）不单独排期**：`shadow-xs`、6px 圆角、lucide 图标这些本来就是原语自带的，只要不去覆盖它们，前三批做完就自然到位。
